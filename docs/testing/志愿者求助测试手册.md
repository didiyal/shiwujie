# 志愿者求助 功能测试手册

> 适用版本：App 3.1.10（versionCode 15）+ 当前线上后端。编写日期 2026-09-14，行为均按当日代码实测逻辑整理。
> 姊妹篇：[紧急求助测试手册](紧急求助测试手册.md)。两条链路共用同一套准备环境。

## 一、功能定义

视障人士在 **AI 页点「志愿者求助」**，系统从「已入队等待的志愿者」中即时匹配一位，双方进入视频通话；任一方挂断后双方状态复位、可再次发起。

关键设计（决定预期结果，先读懂再测）：

1. **匹配是"拉"式的**：不是盲人发起后呼叫志愿者，而是**志愿者先在志愿者端主页点「接听电话」进入等待队列**（Redis 队列，TTL 1 小时，每次入/出队都会刷新），盲人发起时从队列头即时取人。**队列里没人 = 立即失败**，不存在"盲人等待志愿者接听"的长等待。志愿者只要不点取消，1 小时内一直可被匹配；取消后**随时可重新入队**。
2. 匹配在后端同步完成：志愿者 WS 在线 → 立即双方跳视频页；志愿者不在线 → 自动跳过该候选试下一位；全都不在线 → 盲人端收到"没有空闲的志愿者"。
3. 状态机（`videohelp` 表 `help_status`）：`WAITING(0)待响应` → `HELPING(1)通话中` → `END_HELP(2)已完成` / `FALL(3)已取消`。

**关键界面元素**：

- 盲人端 AI 页四个按钮（自上而下）：对话 / 拍照识别 / **紧急求助（红）** / **志愿者求助**。
  TalkBack 焦点朗读："志愿者求助按钮，点击连线志愿者视频帮扶"。

## 三、主流程时序（背下来再测）

```
志愿者B 主页点「接听电话」
   └→ 后端：入 Redis 队列 + videohelp 表 WAITING（channelId=志愿者id）→ B 端显示等待悬浮窗
盲人A AI页点「志愿者求助」
   └→ 前置检查：WS 已连接？token 有效？
   └→ 后端：从队列取 B → 记录置 HELPING → 给 B 发信令 type=1「匹配成功」
B 端：收 type=1 → 停等待悬浮窗 → 给 A 回发 type=2 → 自动跳志愿者视频页
A 端：收 type=2 → 自动跳盲人视频页 → 双方看到对方画面 = 通话建立
任一方点挂断
   └→ 后端：记录置 END_HELP + 计时长 → 给对端发 type=5
对端：Toast「对方已离开通话」→ 视频页自动关闭；双方回 AI 页后可再次发起
```

## 四、测试用例

> 「预期」列含 App 实际 TTS 播报文案；执行时逐条打勾并记实际结果。

### A 组 · 主流程

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| V-01 | 志愿者入队 | B 主页点「接听电话」 | 无报错；出现等待匹配悬浮窗；Redis 队列里能看到 B 的 id |
| V-02 | 盲人发起→即时接通 | A 在 AI 页点「志愿者求助」 | A 端 Toast「正在等待志愿者接听...」后**数秒内**双方都自动跳进视频页，画面互通 |
| V-03 | 通话基础质量 | V-02 通话中互相对话、晃动手机 | 双向音视频正常，无黑屏/卡死 |
| V-04 | 盲人先挂断 | A 挂断 | A 退出视频页；B 端 Toast「对方已离开通话」且视频页自动关闭；videohelp 记录 END_HELP，duration 已写入 |
| V-05 | 志愿者先挂断 | 重新走 V-01~02 后 B 挂断 | 对称：A 端「对方已离开通话」自动退出 |
| V-06 | 挂断后再发起 | V-04 完成后立刻再走一遍主流程 | 双方均能再次接通（验证 type=5 复位生效，无"卡通话中"） |

### B 组 · 空态与边界

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| V-07 | 无志愿者入队 | 确保无人入队，A 点「志愿者求助」 | Toast「当前没有志愿者在线等待，请稍后再试」+ **TTS 同文播报** |
| V-08 | 志愿者重复入队 | B 已在队列中再点「接听电话」 | Toast「您已经在匹配中了」（队列存活期内，即 1 小时内） |
| V-09 | 志愿者长挂等待（3.1.11 新行为） | B 入队后**不动**，等 5 分钟以上，A 发起 | 正常匹配接通——队列 TTL 1 小时，等待期间不再掉队（旧版 30 秒即失效） |
| V-10 | 取消后立即重新入队（3.1.11 新行为） | B 入队 → 悬浮窗取消 → 立刻再点「接听电话」 | 入队成功，无任何等待/拦截；队列过期（1 小时）后的重入也会自动放行（残留 WAITING 过期兜底） |
| V-11 | 队首志愿者掉线 | B、C 依次入队（C 后入）；B 杀掉 App 进程；A 发起 | 后端跳过不在线的 B，匹配到 C，双方进视频（原子匹配回归用例） |
| V-12 | 盲人重复点击 | A 快速连点「志愿者求助」两次 | 第二次被闸门拦下，不重复发请求、不报错 |
| V-13 | 盲人未登录态失效 | 清 App 数据后直接点「志愿者求助」 | 提示登录异常/跳转登录页，不崩溃 |

### C 组 · 网络与重连

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| V-14 | WS 未连接时发起 | A 开飞行模式等 10 秒后关掉，**立刻**点「志愿者求助」（心跳 30 秒安全网还没重连上） | TTS+Toast「网络连接已断开，正在重新连接，请稍等几秒后再试」，不发起匹配（3.1.8 回归） |
